# Watch — v0.8

## Summary

v0.7 opened Watch to the outside — a public self-service report surface and unguessable,
per-user paging. **v0.8 is the operational-depth release: it grows Watch from "incidents +
checks" into a small ServiceNow-`task`-style record set, gives ops a real per-user ingest +
credential story, and hardens the session/password surface that the public tunnel exposed.**

Three threads land together:

1. **Generic ops-record model (ADR-031).** Incidents stay rich and escalation-bearing; **Problem**
   and **RCA** arrive as *thin* records that share one **generic timeline** (a GenericForeignKey, so
   notes/system/AI events attach to any record) and one **generic `RecordLink` table** (Jira-style,
   cross-record links between anything). RCA documents are **assembly-seeded** from an incident's
   annotated timeline and then hand-edited. Every record gets a **human number** (`INC-`/`PRB-`/`RCA-`)
   and a **shared `/ui` detail shell**. No table sprawl, and the Incident keeps its relational
   machinery (SLA, tiers, dedupe, paging) untouched.

2. **Per-environment ops ingest + per-user credentials (ADR-028/029/030).** A schema-less
   **status + digest** ingest/display per environment, authenticated by **per-user API keys** that
   replace the old shared secret, with a **per-user rotation seed** so one knob rolls every derived
   credential (API key + paging topic) at once.

3. **Session & credential hardening (ADR-008).** Long **rolling sessions**, **session revocation**
   (self-service "sign out everywhere" + admin force-sign-out), **split, configurable seed
   passwords** (no more universal `admin/admin`), a **self-service password-change UI**, and the
   **standard password-strength validators**.

Plus the dev-loop work that made the public demo reachable and the gates dependable: a **second
ngrok tunnel** for the status page with a cross-origin edge exemption, **opt-in Playwright browser
install** (kills the macOS pre-commit hang), and **release demo-video storyboards**.

Delivered: **ADR-028, ADR-029, ADR-030, ADR-031**, plus ADR-008 session/password hardening and the
ADR-027 tunnel exemption — 23 commits since `v0.7.0`, five DB migrations (`0013`–`0017`), every
commit landed with ≥90% coverage + a green SonarQube gate + a passing Playwright smoke.

## 1. Generic ops-record model (ADR-031)

The pull was toward the ServiceNow model where `incident`/`problem`/`change` share
number/state/work-notes/audit — but *without* a wide catch-all table, a sprawl of type tables, or
diluting the Incident (which carries genuinely relational machinery: tiers, SLA, Step Functions
tokens, the dedupe partial-unique index, paging, on-call). v0.8 gets that shape with **2 thin models
+ 1 link table + 1 timeline migration**, built in four gated clusters.

**Cluster 1 — the timeline becomes generic.** `TimelineEvent`'s hard `incident` FK became a
**GenericForeignKey** (`content_type` + `object_id`), so notes / system events / AI events — and
their annotations — attach to *any* record. `Transition` (the escalation audit) stays incident-only,
so an incident's timeline is Transitions + TimelineEvents while a Problem/RCA timeline is
TimelineEvents only. `services.timeline()` / `add_note` / `post_system_event` / `post_ai_event` now
take a record. Migration `0013` backfilled the existing events onto the GFK with zero loss. *This
changed TimelineEvent, not Incident.*

**Cluster 2 — Problem + human numbering.** `Problem` is a thin root-cause record
(`title` / `description` / `status` `open→investigating→known_error→resolved→closed` / `assignee` /
`data` JSON) with no escalation. A `RecordCounter` + `numbering.next_number(prefix)` mints
**`INC-`/`PRB-`/`RCA-`** numbers via `select_for_update` (a real row lock on Postgres, a no-op on the
sqlite test path). Incident gained a `number` too, assigned on `save()`; intake assigns it
explicitly because `bulk_create` skips `save()`. Migrations `0014` (counter + `Incident.number` +
Problem) and `0015` (backfill existing incidents oldest-first).

**Cluster 3 — RCA as a stored record.** `Rca` (`title` / `document` markdown /
`status` `draft→in_review→final` / `assignee` / `data`). At creation you optionally pick a source
incident and the `document` is **seeded** by the existing `rca_markdown` assembler (the annotated
timeline + a root-cause / follow-ups scaffold), then hand-edited in a `/ui` editor; the provenance
lands as a timeline event. A live-LLM draft stays a deferred, flagged follow-up. Migration `0016`.

**Cluster 4 — one generic link table.** `RecordLink` has GenericForeignKeys on **both** ends plus a
directed `kind` (`relates_to` / `caused_by` / `duplicate_of` / `blocks`), a `unique(from, to, kind)`
constraint, and from/to indexes. A single table expresses "this RCA is caused by that incident,"
"this problem relates to these incidents," and can point at a **Check** (or anything) without
touching that model. The `/ui` shows links with direction (→ outgoing / ← incoming), each end's
timeline gets a system event on link, and a shared `_links.html` block is embedded on the incident,
problem, and RCA detail pages. Links are added by typing a human number. Migration `0017`.

**Shared surface.** A `/ui` record-detail shell (status/assignee, work notes, links, timeline) is
reused across record types, with per-type list views and `Problems` / `RCAs` nav entries. The MTI
`Record` base is **deferred** — the shared surface can be collapsed under one base later, cheaper
once its shape is proven than guessed now.

**Not yet (by design):** AI-drafted RCA, seeding an RCA over the *union* of several linked records,
Check numbering (a Check is a valid link target but isn't reachable from the number-based add-link
form yet), and the MTI base.

## 2. Per-environment ops ingest + per-user credentials (ADR-028/029/030)

**Status + digests (ADR-028).** Each environment can post a **status** (the whole request body is
arbitrary JSON that drives a schema-less renderer) and **digests** (markdown `content` + optional
`title` + a SPECIAL/ROUTINE flag). A session-authed, ops-facing `/ui/environments/` page renders the
latest per-environment status via a recursive JSON node partial and lists digests with a
Copy-for-Slack button.

**Per-user API keys (ADR-029).** The shared ingest secret is replaced by **per-user keys** —
`wk_<id>_<hmac>`, HMAC-derived from a server secret so nothing extra is stored, shown to each user on
`/ui/settings/` with ready-to-paste `curl` examples. Ingest authenticates *as a user*.

**Rotation seed (ADR-030).** Each user has a rotation seed; rotating it rolls **all** derived
credentials together — their API key **and** their salted ntfy paging topic — from one button.

## 3. Session & credential hardening (ADR-008)

- **Rolling sessions** — an active user stays signed in (sliding expiry), with the session-theft
  tradeoff reasoned out in the ADR; revocation, not a short TTL, is the real lever.
- **Session revocation** — self-service **"sign out everywhere"** (kills the user's other sessions,
  keeps the current device) via a server-side session reverse-index, plus a Django-admin
  **force-sign-out** action for a superuser. Instant, unlike a stateless JWT.
- **Split, configurable seed passwords** — `seed_demo` no longer bakes in `watch` / `admin/admin`.
  `SEED_USER_PASSWORD` and `SEED_ADMIN_PASSWORD` (defaults `watch` / `admin` for pure-local
  convenience) are **re-applied every run**, so editing `.env` + re-seeding rotates the creds; the
  seeder no longer echoes the password.
- **Self-service password change** — a form on `/ui/settings/` backed by Django's
  `PasswordChangeForm`; `update_session_auth_hash` keeps the current device signed in after the
  change.
- **Stronger validators** — the lone min-length validator is joined by the common-password,
  user-attribute-similarity, and all-numeric validators, so weak self-chosen passwords are rejected.

## 4. Dev loop, tunnels & release tooling

- **Second ngrok tunnel** for the status-page SPA (`status:5173`) alongside the API tunnel
  (`watch:8010`), each started/stopped independently (`tunnel.sh`), with a per-agent web-addr so the
  two agents don't collide on `:4040`. The SPA takes an `?api=` override to point at the API tunnel,
  and the edge traffic-policy **exempts the public `AllowAny` endpoints** (`/api/status`,
  `/api/report/*`) from basic-auth so the browser's cross-origin `fetch`/POST reaches Django while
  everything else (`/ui`, `/admin`, DRF) stays password-walled (ADR-027).
- **Opt-in Playwright browser install** — `E2E_INSTALL` now defaults to `0`. On macOS the
  `npx playwright install` unzip hangs forever, which turned a plain `git commit` into a 5-minute
  freeze in the pre-commit smoke stage. Browsers are seeded out-of-band with `ditto`; opt in with
  `E2E_INSTALL=1` where the installer works. CI is unaffected (prebuilt Playwright image).
- **Release demo-video storyboards** + `make demo` (shot-scraper) for recording short clips of
  user-facing features at release time.

## Migrations

Apply with `python manage.py migrate` (or `make dev`, which migrates + seeds):

| Migration | What |
|---|---|
| `0013_timelineevent_generic_target` | TimelineEvent `incident` FK → GenericForeignKey (+ backfill, zero loss) |
| `0014_recordcounter_incident_number_problem` | `RecordCounter`, `Incident.number`, `Problem` |
| `0015_backfill_incident_numbers` | assign `INC-###` to existing incidents (oldest-first) + seed the counter |
| `0016_rca` | `Rca` stored record |
| `0017_recordlink` | generic `RecordLink` (from/to GFK + kind, unique + indexes) |

All additive; the Incident lifecycle/engine is untouched.

## Operator notes

- **Seed passwords:** set `SEED_USER_PASSWORD` / `SEED_ADMIN_PASSWORD` in `.env` (non-guessable) on
  any tunnel-exposed box, then re-run `seed_demo` to rotate. `make e2e` reads `SEED_USER_PASSWORD`
  from `.env` so the smoke logs in with the real seeded password (falls back to `watch`).
- **Ops ingest:** each user's key + `curl` examples are on `/ui/settings/`; rotate from the same
  page. Server secret via `API_KEY_SECRET` (SSM in prod).
- **Tunnels (dev):** the watch tunnel keeps ngrok edge basic-auth; only `/api/status` and
  `/api/report/*` are exempt. New public endpoints must be added to that exemption expression.
- **e2e (dev):** seed browsers with `ditto` (see `e2e/README.md`); commits run the real smoke via
  `E2E_INSTALL=0` (the default).

## Compatibility

Per the release convention, `watch` / `platform` / `watchtower` bump to **v0.8** together as a
tested-together, verified-compatible attestation. No cross-repo contract changed in this release —
v0.8 is app-side depth (records, ingest, auth) on top of the v0.7 platform.
