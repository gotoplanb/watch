# Watch — v0.11

## Summary

**The assistant tier arrives — watch starts running its own operations manual.** v0.11 turns the
"Highway Mode, Race Mode" doctrine from prose into running code: operating modes as domain state,
a deterministic check→incident bridge, a Tier-1 triage assistant held to an advisory contract, a
declarative routing matrix, and an MCP server so AI assistants operate watch as first-class
(audited) responders. Plus a UI doctrine — mobile-first, WCAG 2.1 AA — enforced by a gate.

## Operating modes (ADR-035)

`highway` (default: healthy until proven otherwise) vs `race` (release windows: healthy must be
proven) as **audited domain state**, not a feature flag: an append-only `OperatingModeWindow`
carries who declared it, why, and the all-clear; `modes.current_mode()` is the single read path;
every automated decision function takes mode as a parameter from day one.

## Check→incident bridge + T1 triage (ADR-036)

A `SessionCheck` finishing `errors_found` now opens an incident through the existing idempotent
intake — dedupe keyed on the **check subject**, so a flapping subject corroborates its open
incident instead of flooding — provenance-linked via a new `created_from` record link. Triage
follows: **AI classifies, code disposes.** The assistant (pluggable `stub | bedrock | conduct`,
the ADR-034 pattern) returns only `(responsibility, fault_domain, verdict, confidence,
rationale)`; the disposition is deterministic. Every decision is an append-only `TriageDecision`
— the substrate for the manual's escalation-correctness KPI. Assistant failures soft-fail; the
SLA engine remains the backstop.

## Declarative routing matrix (ADR-037)

`backend/triage-matrix.yaml` is the single policy artifact humans review and code executes:
status/origin → `responsibility × fault_domain` (outbound `client`-kind spans read as vendor),
mixed evidence aggregates by precedence, and the `(verdict × cell × mode)` disposition table
encodes the race-mode principle — **internal faults during a release window auto-escalate T1→T2**
(escaped-defect presumption); vendor/client cells don't change because *we* shipped. The AI is
the **fallback** for unmatched evidence only; most incidents triage with zero model calls, and
`TriageDecision.provider` records which path decided. Building this exposed and fixed a latent
ADR-026 gap: Tempo's search API only returns queried attributes, so `http_status`/`name` had
never populated (`| select(...)` added). Verified live against Watchtower Tempo across all five
paths, including race-mode auto-escalation with zero AI calls.

## Watch as an MCP server (ADR-038)

Nine tools (`list_incidents`, `get_incident`, `acknowledge`, `escalate`, `resolve`,
`run_session_check`, `get_operating_mode`, `open/close_race_window`) with a **uniform surface
and server-side tier authz** — capability is per-incident and per-call, so the tool list never
filters; denials teach ("requires T2-or-higher; you hold T1"). Two credentials, one principal:
a derived `wm_` MCP key (one rotate rolls ingest + MCP + ntfy) and a minimal **OAuth 2.0 AS**
(auth-code + PKCE, rotating refresh, tokens bound to the approving *user*) for claude.ai
connectors. Runs as `manage.py mcp` — same image, different command (ADR-025/032). `/ui/settings`
gained the connection section. Verified live end to end, including the full browser OAuth flow.

## UI doctrine + accessibility gate (ADR-039)

Mobile-first (base styles are the phone design; no page scrolls horizontally at any viewport),
Tailwind-only (`[x-cloak]` is the lone raw-CSS exception; the ops renderer's hand-written block
is gone), and **WCAG 2.1 AA with zero violations** — ~90 sub-AA contrast usages raised, every
form control named, inline links underlined. Enforced by `e2e/a11y.spec.ts` (axe-core — the
engine inside Lighthouse — at 390px and desktop) in the same tiered suite that runs at
pre-commit locally and in the pipeline's staging Smoke stage. The gate's own plumbing caught a
latent smoke-test bug: the login URL assertion also matched the login page's `?next=` query.

## Developer experience

`make dev` hot-reloads: the OTel bootstrap now skips only the autoreloader's watcher parent
(`RUN_MAIN` gate), so telemetry stays single-instance while stale-server failures become
"save, wait a second" instead of a phantom smoke-test failure.

gate green (all new hotspots reviewed with rationale). In flight, not in this release: the
mobile UX phase-2 redesign (watch#47, `mobile-ux-phase2` branch).
