# Watch — v0.9

## Summary

v0.8 was app-side depth. **v0.9 is the reliability release — hard-won knowledge from a
build-mode incident turned into guardrails and doctrine.** On 2026-07-07 a full day of "about
as disastrous as it can be for something that isn't receiving production traffic" churn hit the
**local lifecycle scripts**: a `teardown` that silently ran as the *management* identity because
account-id env vars weren't loaded; a background `brew` upgrade to **OpenTofu 1.12** whose new
resource-identity check broke cross-account `destroy` after ~100 clean runs; and partial-apply
**orphans** that quietly billed. None of it touched production traffic — that only ever changes
through the CI/CD pipeline — but it exposed how much of the estate's day-to-day safety rode on an
operator's shell being *exactly* right.

**v0.9 makes the lifecycle scripts fail loud instead of failing wrong**, and writes down *why*
the scary day was a build-tool problem and not a production one. Almost all the code lands in the
**platform** repo (`~/platform`); watch's contribution is the governing decision (**ADR-032**) plus
the release-process and operating-mode groundwork that keeps this knowledge from being lost to a
context compaction. No application code, schema, or cross-repo contract changed — so this is a pure
reliability/attestation bump, tagged in lockstep.

Six threads land together:

1. **Root-cause fix — pin the toolchain.** OpenTofu is pinned to **1.11.11** (the last line before
   the 1.12 identity check) via a repo-local `.bin/tofu` + `.opentofu-version`, resolved through
   `TG_TF_PATH`. The pin is **single-sourced**: the scripts *and* both CI workflows read the same
   file, so the two can never drift again (`#46`).
2. **Fail-fast guardrails.** A new `lib/preflight.sh` aborts **before any mutation** on a bad AWS
   identity, missing/malformed member account IDs, or a missing Cloudflare token for a DNS op; a
   `lib/tofu.sh` assertion refuses to run on a drifted toolchain (`#43`/`#46`). Plus the specific
   bug that started the day: `teardown.sh` now loads `.env` **unconditionally**.
3. **Drift detection + a reviewed force-clean.** `make doctor` (`#44`) is a read-only, cross-account
   sweep for **orphans** (billable leftovers teardown missed) and **ghosts** (in state, gone from
   AWS). `make nuke` (`#45`) is the reviewed, dependency-ordered last-resort force-clean with an
   explicit **PERSIST allowlist** and a typed-target confirmation — the consolidation of the
   improvised cleanup scripts from that day.
4. **The doctrine (ADR-032).** *Two delivery paths, two guarantees* — production rides the pipeline
   (OIDC, least-privilege, plan-then-apply, promote-by-digest, prod-approval gate); the lifecycle
   scripts are a **build-velocity tool**, differently safe by design. "Are the scripts reliable?"
   and "is production reliable?" are now separate questions with separate answers.
5. **Structural symmetry + operability.** Staging's DNS is split into `dns` (the API record) +
   `dns-status` (the CloudFront/status record), mirroring prod (ADR-020), so a CloudFront outage or
   the new-account verification hold blocks **only** the status page, never the API by name. The two
   AWS new-account activation holds (CloudFront verification, CodeBuild 0-quota) are documented with
   ready-to-file support-case text.
6. **Process & continuity.** A written **release process** (patch/minor/major readiness), a
   **major-release checklist** that now mandates an ADR/doc audit and aggressive dependency pinning
   (informed directly by this incident), and a CLAUDE.md **operating-mode** section re-emitted by a
   SessionStart hook so the build-mode context survives a compaction.

## 1. Root-cause fix — pin the toolchain (`#46`)

The disaster's true cause was not a code change; it was **tooling drift**. A background
`brew upgrade` moved OpenTofu from the 1.11 line to **1.12.2**, which introduced a resource-identity
check that throws `Error: Unexpected Identity Change` when a resource created under an assumed
member-account identity is read during a **destroy refresh** — precisely the cross-account teardown
path. ~100 prior teardowns had been clean; the only thing that changed was the binary on `PATH`.

v0.9 pins OpenTofu to **1.11.11** and stops trusting `PATH`:

- **`.opentofu-version`** holds the single source of truth (`1.11.11`).
- **`scripts/tofu-pin.sh`** (`make tofu-pin`) downloads that exact version into a git-ignored
  `.bin/tofu`; `scripts/lib/tofu.sh` resolves `TG_TF_PATH` to it (auto-pinning on first use) in
  preference to whatever `tofu` a shell happens to have.
- **CI single-sources the same file.** `terragrunt-plan.yml` and `terragrunt-apply.yml` previously
  hardcoded `tofu_version: "1.12.2"` — the exact broken version, *and* a divergence from local. They
  now read `.opentofu-version` into the `setup-opentofu` input, so the pin changes in **one file**
  and CI can't drift from the scripts.

## 2. Fail-fast guardrails (`#43`, `#46`)

The teardown that ran against the wrong account did so because `WATCH_{NONPROD,PROD}_ACCOUNT_ID`
weren't exported, so Terragrunt's cross-account `assume_role` fell back to the **management** user —
where every member-account destroy is `AccessDenied`, and the run limps forward doing partial,
wrong-account work instead of stopping.

- **`scripts/lib/preflight.sh`** is sourced by `create` / `teardown` / `doctor` / `nuke` and runs
  **before any mutation**. It asserts a valid AWS identity (`sts get-caller-identity`), that — when
  cross-account — **both** member account IDs are present and well-formed (12 digits), and that a
  DNS-touching op has `CLOUDFLARE_API_TOKEN`. Any failure prints a `FATAL` line naming the exact gap
  and exits 1 before a single resource is touched. The teardown that started the incident would now
  abort with `FATAL: WATCH_NONPROD_ACCOUNT_ID unset/malformed`.
- **`scripts/lib/tofu.sh`** asserts the resolved tofu matches `.opentofu-version` and hard-fails on a
  mismatch (`TOFU_PIN_SOFT=1` downgrades to a warning for read-only/plan use). The silent 1.12 bump
  would now abort with `FATAL: OpenTofu 1.12.2 != pinned 1.11.11`.
- **`teardown.sh` loads `.env` unconditionally.** The old guard only sourced `.env` when a (wrong)
  variable was already set — so a plain `make teardown` in a fresh shell had no account IDs. It now
  always loads `.env`; a teardown with no `.env` is treated as the error it is.

## 3. Drift detection + a reviewed force-clean (`#44`, `#45`)

Two first-class tools replace the ad-hoc cleanup that consumed most of the incident:

- **`scripts/doctor.sh` (`make doctor`)** — read-only, cross-account. It assumes into **both** member
  accounts and reports **ORPHANS** (billable `watch-*` resources live in AWS that teardown missed —
  the silent-billing failure) and, with `--state`, **GHOSTS** (tracked in Terraform state but absent
  in AWS — a stale apply/refresh would error or recreate). Exits nonzero on orphans so it can gate a
  teardown. Verified clean against the live billing-zero estate across both accounts.
- **`scripts/nuke.sh` (`make nuke TARGET=…`)** — the reviewed, in-tree consolidation of the
  hand-written cleanup scripts. Dependency-ordered with waits (ECS → ALB/TG → Lambda → ElastiCache →
  RDS → NAT → subnet groups → EIP → KMS/SSM/AppConfig/SQS → VPC + deps), idempotent, with a
  **typed-target confirmation** and an explicit **PERSIST allowlist** it never touches: the tf-state
  backend, the ECR repo + `:bootstrap` image, ACM certs, the `watch-ci-*` / `watch-prod-deploy` IAM
  identities, and `org`/`account`/`github`. So the next "teardown left orphans" is one audited
  command instead of improvised AWS-CLI under pressure.

## 4. The doctrine — ADR-032, two delivery paths

The reason the day *felt* like an indictment of production reliability is that two paths to the
estate had been conflated. **ADR-032** draws the line:

- **Path A — the production pipeline** (GitHub Actions → CodePipeline → CodeBuild → cross-account
  CodeDeploy, ADR-020): short-lived OIDC creds, least-privilege roles, plan-before-apply,
  promote-by-digest (ADR-017), a prod-approval gate. **The mechanism of record for anything reaching
  production traffic.** Optimizes for correctness/auditability/reversibility.
- **Path B — the local lifecycle scripts** (`make create/teardown/nuke/doctor/…`): human + bootstrap
  admin creds, whole-estate churn for build velocity. Optimizes for speed. **Not** the production
  change mechanism — *differently safe*, its floor held by the `#43`–`#46` guardrails.

The boundary rule: production app changes flow **only** through Path A; estate lifecycle is Path B's
job **during ACTIVE BUILD MODE** (a time-boxed exception, not the steady state). Reliability is
measured per path — production rests on Path A + IaC + gates, which the incident never touched.

## 5. Structural symmetry + operability (ADR-020)

- **Staging DNS split.** Staging's single DNS stack became `dns` (the `watch.<domain>` → ALB record,
  depends only on `app`) + `dns-status` (the `status.<domain>` → CloudFront record, depends on
  `frontend`), each `count`-gated on its target being set — mirroring the prod split. A CloudFront
  outage, or the new-account verification hold, now blocks **only** the status page; the API stays
  resolvable by name. (`teardown.sh`'s stack list was updated dependents-first in the same change —
  a new stack that isn't in the teardown list becomes a billable orphan.)
- **New-account holds, documented.** Fresh Organizations member accounts draw a non-deterministic
  subset of two fraud-prevention holds — a **CloudFront** "account must be verified" block and a
  **CodeBuild** account-level 0-concurrent-build limit (not a Service-Quotas knob). `docs/support-cases.md`
  carries ready-to-file, account-ID-parameterized case text for both.

## 6. Process & continuity

- **Release process written down** (`docs/releases/README.md`): what patch/minor/major mean, the
  lockstep attestation model, and a worked example. This notes file follows it.
- **Major-release checklist hardened** by this incident: it now mandates a full **ADR & documentation
  audit** (the written record must catch up to the code at a major) and **aggressive dependency
  pinning** — with the OpenTofu 1.12 break as the cautionary example.
- **Operating-mode continuity.** A CLAUDE.md *ACTIVE BUILD MODE* section states plainly that
  create/teardown/manual deploys are routine build-mode operations (not scary one-offs), and a
  `SessionStart` hook re-emits it after every compaction so the context isn't lost mid-build.

## Operator notes

- **After any teardown, run `make doctor`** — it's the cross-account orphan/ghost check (nonzero exit
  = something billable lingers). `make sweep` remains the single-account read-only variant.
- **`make nuke TARGET=nonprod|prod|both`** is the **last resort** when teardown leaves orphans
  `doctor` flags — never the routine path. It requires typing the target to confirm and preserves the
  PERSIST allowlist. After a nuke, state references deleted resources (ghosts); a following
  `make create`/`teardown` reconciles.
- **Toolchain:** run `make tofu-pin` once to install the pinned tofu into `.bin/tofu`; the scripts
  auto-pin on first use. If you deliberately need a different tofu for a read-only op, set
  `TOFU_PIN_SOFT=1` to downgrade the version assertion to a warning. **Do not `brew upgrade` tofu and
  expect cross-account teardown to work** — 1.12's identity check breaks it.
- **`.env` is mandatory for lifecycle ops** and gitignored — it carries `WATCH_*_ACCOUNT_ID`
  (cross-account assume-role) and `CLOUDFLARE_API_TOKEN` (DNS). Preflight will abort loudly if it's
  missing or malformed.

## Compatibility

Per the release convention, `watch` / `platform` / `watchtower` bump to **v0.9** together as a
tested-together, verified-compatible attestation. **Unusually, the substance this cycle is in the

reliability + doctrine release on top of v0.8.
