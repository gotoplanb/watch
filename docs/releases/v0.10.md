# Watch — v0.10

## Summary

Two threads land together in v0.10.

**AI-drafted RCA (the headline).** The RCA assembly shipped in v0.8 — `rca_markdown` renders an
incident's annotated timeline into clean, reviewable Markdown — always earmarked an LLM follow-up
that would draft the narrative sections a human otherwise hand-writes. v0.10 delivers it, behind the
`rca_ai_draft` flag, and does so as a **pluggable provider** rather than a single vendor binding:

- **`bedrock`** — Claude Sonnet on Amazon Bedrock, the deployed/cloud backend, keeping the model call
  inside the account's IAM/VPC/CloudWatch boundary (no third-party API key). **ADR-033.**
- **`conduct`** — local models (Ollama) via the sister **conduct** project over a synchronous HTTP
  call, the local-dev backend: no AWS, no model-access grant, iterate on AI-RCA *today*. **ADR-034.**
- **`stub`** — a deterministic, marked, no-network draft; the default and what hermetic tests use.

One instruction prompt (`rca_ai.SYSTEM_PROMPT`), owned by Watch, is handed byte-identical to whichever
backend runs; provenance names the model that *actually* ran (e.g. `gemma4:e4b`); any failure is a
soft-fail — a flash, document untouched, never a 500. Verified end-to-end locally against a real
Conduct gemma draft.

**Estate resilience (the substance in `platform`).** New AWS Org member accounts hit
account-verification holds (CloudFront, and a 0-quota on CodeBuild) that blocked the frontend and CD.
v0.10 records the response: the whole estate was **cut over to a pair of fallback member accounts**,
which surfaced — and fixed — **four latent pipeline bugs** the old CodeBuild hold had been masking, got
CD green through staging to the prod-approval gate, repointed the **GitHub-Actions CI plane** to the
new accounts, and added a **local AWS access portal** (`make portal`) so signing into member accounts
for support tickets stops being a chore. Teardown-to-non-billing was re-verified clean across both
accounts. Substance lives in `platform`; watch carries the AI-RCA feature + the decisions.

**No schema change** — the latest migration remains `0017`. Unit tests green at **98.89%** coverage
(the three new AI-RCA provider modules at 100%); SonarQube gate green.

Full decisions: **ADR-033** (Bedrock), **ADR-034** (pluggable provider / Conduct) in
[`watch-adrs.md`](https://github.com/gotoplanb/watch/blob/main/watch-adrs.md).

## 1. AI-drafted RCA — assembly to narrative

`services.rca_markdown(incident)` already produced the clean, reviewable input a root-cause writeup
starts from. v0.10 adds `services.draft_rca(rca)`: it sends that assembly to the configured model,
**replaces the document** with the returned Markdown (a starting point the human then edits — never an
auto-published RCA), and records provenance as a system timeline event. It's reached only through the
`rca_ai_draft` flag (ADR-003): the UI hides the **✨ AI draft** button and the `ui:rca_ai_draft` view
returns 403 when off. A confirm guards the destructive overwrite; the RCA lifecycle (`draft → in_review
→ final`) and human ownership are unchanged.

## 2. One seam, three backends (`incidents/rca_ai.py`)

The provider is a config choice, not a code change — `RCA_AI_PROVIDER ∈ {stub, bedrock, conduct}`:

- **`rca_ai.py`** is the seam: `draft(source) -> DraftResult(text, provider, model)`, the single
  shared `SYSTEM_PROMPT`, and the deterministic `stub`. Provider modules import lazily (no boto3/requests
  cost at import, no cycles).
- **`bedrock.py`** (ADR-033) — the Converse call to Claude Sonnet; the deployed backend. The model
  call stays inside the account boundary (deviation from the ADR-021/031 "Anthropic API" sketch,
  recorded in ADR-033); `bedrock:InvokeModel` is least-privilege on the app task role in `platform`.
- **`conduct.py`** (ADR-034) — a synchronous `POST /jobs` to Conduct's local models (Bearer key,
  incident tier → Conduct `task_type`). Conduct's primaries are pinned resident, so the draft returns
  inline — no async job/poll. **Watch owns the prompt** and sends it every call, so it can't drift
  from the Bedrock path.

Every backend raises `rca_ai.DraftError` on any failure; the view degrades to a flash and leaves the
document intact. `BEDROCK_LOCAL_MODE` is gone — folded into `RCA_AI_PROVIDER=stub`.

## 3. Estate cutover to fallback accounts + latent-bug fixes

The new primary member accounts were held at account verification (CloudFront) and CodeBuild quota,
blocking the status-page frontend and continuous delivery. Rather than wait, the entire estate was
**recreated in a pair of fallback member accounts** — a clean exercise of the disposable-estate
lifecycle and the path-keyed, account-agnostic Terraform state. The cutover immediately surfaced **four
latent bugs** that the long-standing CodeBuild hold had hidden, each now fixed in `platform`:

- the CodeBuild **build role** lacked `kms:Decrypt` on the artifact CMK;
- **DAST + Smoke** roles had the same gap;
- the build promoted **prod** Lambdas cross-account (now **staging-only**, prod deferred);
- the Smoke stage authenticated the **checks** webhook with the *intake* secret (401) — now the
  distinct `CHECKS_WEBHOOK_SECRET` is injected from SSM.

With those closed, CD ran green Source → Build → DeployStaging → DAST → Smoke to the **prod-approval
gate**, and a follow-up push proved SUPERSEDED behavior (a newer commit replaces an older one waiting
at the gate).

## 4. Delivery-plane repointing + local access portal

- **GitHub-Actions CI plane** repointed to the fallback accounts: the `watch-ci-trigger` role (push →
  `StartPipelineExecution`), the read-only `watch-ci-plan` roles, and the `github-oidc` assume grants —
  verified live (trigger + `terragrunt-plan` via PR). Documented as an explicit cutover step.
- **`make portal`** (`scripts/aws-portal.py`) — a small local access portal that lists member accounts
  from a gitignored JSON and opens per-account switch-role links, so making support tickets across
  accounts stops meaning manual role hunting. An IAM-Identity-Center-style convenience for a
  role-in-member-accounts world (the shape a day-job deployment will need — tracked in watch#47).
- **Teardown-to-non-billing re-verified**: `make doctor` reports both fallback accounts clean of every
  billable resource; only the intentional foundation (tf-state, ECR, ACM) persists. One teardown
  wrinkle — AppConfig deletion protection on the `config` stack — filed as platform#49.

## 5. UI & DX polish

- **Record linking is usable** — the add-link UI now shows human numbers, parses forgivingly, and
  flashes feedback (it silently no-op'd before).
- **iOS focus-zoom killed** — form controls are `text-base` on phones (Tailwind utilities only, no
  hand-written CSS), so tapping an input no longer zooms.
- **Responsive mobile nav** — the header collapses to a hamburger below `md`; brand is just "Watch";
  the current section is highlighted.
- **`make dev` seeds with `.env` creds** (shared `SEED_CMD`) — a restart no longer resets rotated
  passwords to defaults; the runserver now sources `.env` so local app config (incl. Conduct) reaches
  the app; `make seed-dev` added; `make help` is auto-generated (matches platform/watchtower).
- **RULE 0** written into CLAUDE.md — use the project's own make targets/scripts before ad-hoc probing.
- Status page drops the open-incident count tiles (not for public eyes); Playwright bumped
  1.49 → 1.61.1 (GHSA-7mvr-c777-76hp).

## Migrations

**None.** v0.10 adds no models or schema — the latest migration remains `0017`. The AI-RCA feature is
pure service/provider code behind a flag.

## Operator notes

- **Pick a provider per environment.** `RCA_AI_PROVIDER` = `stub` (default, no network) / `conduct`
  (local dev — set in `.env`, needs Conduct running with a `watch` client key) / `bedrock` (cloud —
  set in the `platform` task def).
- **Bedrock is still gated on a manual grant.** The deployed Bedrock path is inert until **per-account
  Bedrock model access is granted in-console** (a manual step, like the CloudFront hold) *and* the flag
  is on — until then it soft-fails with a flash, never a 500. Tracked in **watch#40**.
- **Conduct locally:** `CONDUCT_BASE_URL` (host-side `make dev` uses `localhost:8000`; `.env` keeps
  `host.docker.internal` for in-compose), `CONDUCT_API_KEY` from `.env` (never inline), and
  `CONDUCT_TASK_TYPE` (default `tier_2`).
- **Estate now lives in the fallback member accounts.** Lifecycle and CI target those; `make portal`
  lists them.

## Compatibility

Lockstep **v0.10.0** across **watch**, **platform**, and **watchtower** — the tested-together,
verified-compatible attestation (not semantic versioning). watch carries the AI-RCA feature; platform
carries the estate cutover + AI-RCA cloud enablement (IAM + provider env); watchtower is a compatibility
attestation (auto-gen `make help` only this cycle). The three were exercised together locally — the
Watch backend against watchtower's SonarQube gate and OTLP path — before tagging.
